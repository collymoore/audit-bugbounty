🚀 Executive Summary

This report presents the results of an external security assessment of CardNET (Consorcio de Tarjetas Dominicanas S.A.), the Dominican Republic's primary payment processor. The assessment identified 25 findings across 22 live subdomains, including 2 critical, 6 high, 13 medium, and 4 informational vulnerabilities.

🔴 Overall Risk Level: CRITICAL
CardNET operates as a payment processor handling sensitive financial data but exposes three End-of-Life products (Odoo v11, IdentityServer4, AngularJS) and two production Odoo ERP instances with publicly accessible database manager pages. The combination of EOL software + exposed management interfaces + payment processing context creates an elevated risk of data breach or ransomware.

CVE-2018-14885 Exploit Surface

This vulnerability allows an attacker to restore a database dump without knowing the super-admin password. An arbitrary password succeeds. This grants full database access including all financial transactions, customer data, and payment configurations.

🟡 Medium

POS terminal authorization grant. Potential for fraudulent terminal enrollment. High impact if exploitable.

🟡 Medium

M3 — Custom Grant: external_credentials

External token exchange. Risk of issuer confusion if validation is weak.

🟡 Medium

M4 — Device Code Phishing

Device authorization flow enabled. Standard phishing vector — attacker initiates flow, victim authenticates on their device.

🟡 Medium

M5 — PKCE 'plain' Supported

IdentityServer4 supports PKCE 'plain' (no S256). Weaker than S256 — susceptible to interception if TLS is compromised.

🟡 Medium

M6 — Single JWKS Key, No Rotation

Only one RSA256 signing key exposed. No rotation mechanism visible. Key compromise would allow full token forgery.

🟡 Medium

M7 — Public Introspection Endpoint

Token introspection at /connect/introspect publicly accessible (requires client credentials, but no network restriction).

🟡 Medium

M8 — AngularJS ReDoS (CVE-2022-25844)

Regular expression DoS in AngularJS could take down the BackOffice Comercios with crafted input.

🟡 Medium

M9 — HPKP Weak Pinning

HPKP includes SHA256 of empty string as backup pin (47DEQpj8HBSa+...). Weak practice that could allow MiTM.

🟡 Medium

M10 — Session Cookies Without Auth

Odoo instances issue session cookies (session_id) via GET without authentication. 90-day expiry on cookies.

🟡 Medium

M11 — CVE-2024-39694 (Open Redirect)

IdentityServer4 open redirect. Not directly exploitable without valid client_id, but risk increases if client credentials leak.

🟡 Medium

M12 — NCF Module (ncfonnet)

Custom Odoo module for Dominican NCF tax receipts. Accessible without auth, returns HTTP 500. Undefined behavior with correct params.

🟡 Medium

M13 — LAB Environment Without WAF

lab.cardnet.com.do and mercury.cardnet.com.do have no Imperva WAF protection. Direct origin access to ASP.NET apps.

🛡️ Recommendations

🚨 Immediate (0–72 hours)

  1. Close DB manager on both Odoo instances — block /web/database/manager* via WAF/nginx, set list_db=False in odoo.confCritical
