Data Breach en Plataforma de Servicios

Marketplace Dominicano — Exposición Total de Base de Usuarios

SEC-2026-001
09 Julio 2026
CRÍTICO — Data Breach Confirmado

7,452 perfiles de usuarios expuestos

Plataforma dominicana de servicios del hogar — Firestore sin restricciones permitió acceso total a la base de datos de usuarios.

Clasificación: 🔴 CRÍTICO CVSS: 9.1 Plataforma: ddtteayuda.com Tipo: Firebase Firestore Data Breach Estado: CORREGIDO (10 Jul 2026)
Resumen Ejecutivo: La colección profiles de Firebase Firestore permitía a cualquier usuario autenticado leer la totalidad de los 7,452 perfiles registrados en la plataforma. No se requería rol administrativo ni privilegio especial. No existía verificación de pertenencia del dato. La vulnerabilidad fue corregida aproximadamente 24 horas después de la notificación.

Vulnerabilidades Identificadas

VULN-01: Firestore Data Breach — Colección "profiles" ExpuestaCRÍTICO

Descripción: Reglas de seguridad de Firestore permitían a cualquier usuario autenticado leer la colección profiles completa, sin filtrar por propietario del dato.

Regla vulnerada: allow read: if request.auth != null; — sin verificación de request.auth.uid == resource.id

VULN-02: Registro de Cuentas Sin ProtecciónALTA

Firebase Auth permitía crear cuentas vía REST API sin CAPTCHA, verificación de email ni rate limiting. Cualquier atacante puede crear cuentas masivamente para probar accesos.

POST /v1/accounts:signUp?key=AIzaSyBmsiSrpJwqO6OvsXMLAtTFJuCCMn-KT5o
{"email":"x@y.com","password":"Pass123!","returnSecureToken":true}

Verificado: 4 cuentas creadas en menos de 10 segundos.

VULN-03: Autenticación Sin Rate LimitingALTA

5 intentos de inicio de sesión con contraseña incorrecta en menos de 1 segundo sin bloqueo ni degradación. Permite ataques de fuerza bruta contra cuentas de usuario.

POST /v1/accounts:signInWithPassword?key=AIzaSyBmsiSrpJwqO6OvsXMLAtTFJuCCMn-KT5o
{"email":"usuario@test.com","password":"WRONG","returnSecureToken":true}

Respuesta: INVALID_LOGIN_CREDENTIALS (x5 en 0.8s)
VULN-04: API Key Expuesta en Código ClienteMEDIA

Clave de API de Firebase Web hardcodeada en el bundle JavaScript de Vite, accesible públicamente desde el navegador.

Recomendaciones

  1. Reglas de Firestore: Restringir lectura de profiles a request.auth.uid == resource.id — cada usuario solo puede leer su propio perfil
  2. Rotar API Keys: Regenerar todas las claves Firebase y aplicar restricciones por plataforma (web, iOS, Android)
  3. Notificar a usuarios: Comunicar a los 7,452 usuarios sobre la exposición de sus datos personales
  4. Firebase App Check: Implementar verificación para asegurar que solo la app legítima pueda acceder
  5. Rate limiting: Configurar protección contra abuso en endpoints de autenticación
  6. Auditar todas las colecciones: Verificar que ninguna otra colección esté expuesta
  7. Revisar reglas de Storage: Verificar acceso a Firebase Storage
