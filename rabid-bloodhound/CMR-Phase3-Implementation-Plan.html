Dominio 1: Arquitectura de Seguridad Zero Trust

Objetivo: Reemplazar el modelo actual de confianza implícita (cualquiera puede llamar cualquier endpoint) por un modelo de verificación continua.

Hallazgos referenciados: CMR-01, CMR-02, CMR-03, CMR-04, CMR-05, CMR-06

1.1 API Gateway con Autenticación Centralizada ALTO

Problema: 9 servidores WCF exponen endpoints directamente sin capa de autenticación previa.

Solución: Implementar API Gateway (Ocelot para .NET / Kong / Apache APISIX) como punto único de entrada. El Gateway valida tokens JWT antes de enrutar a los servicios WCF internos.

Implementación:

# Arquitectura propuesta # Antes: Cliente → WCF Endpoint (sin auth) # Después: Cliente → API Gateway (valida JWT) → WCF Endpoint (confía en Gateway) ↑ Identity Provider (Auth0/Keycloak/.NET Identity)

Configuración Ocelot (ejemplo para .NET):

{ "Routes": [ { "DownstreamPathTemplate": "/HisWebServicios/Portal/ServicioPortal.svc/{everything}", "DownstreamScheme": "https", "DownstreamHostAndPorts": [{"Host": "localhost", "Port": 8081}], "UpstreamPathTemplate": "/api/v1/{everything}", "AuthenticationOptions": { "AuthenticationProviderKey": "Bearer", "AllowedScopes": [] }, "RateLimitOptions": { "ClientWhitelist": [], "EnableRateLimiting": true, "Period": "1m", "PeriodTimespan": 60, "Limit": 30 } } ], "GlobalConfiguration": { "BaseUrl": "https://api.cmrmedical.com" } }

Esfuerzo: 40-60 horas-hombre | Dependencias: Identity Provider, Gateway server | Risk reduction: 90%

1.2 Autenticación JWT para Endpoints SOAP MEDIO

Problema: Los endpoints WCF actualmente no requieren autenticación.

Solución: Implementar WCF Custom Authorization Manager que valida tokens JWT en el header HTTP Authorization antes de procesar cualquier operación.

Código de implementación (C# WCF):

// Custom Authorization Manager para WCF public class JwtAuthorizationManager : ServiceAuthorizationManager { protected override bool CheckAccessCore(OperationContext operationContext) { var request = operationContext.RequestContext.RequestMessage; var property = request.Properties[HttpRequestMessageProperty.Name] as HttpRequestMessageProperty; var authHeader = property?.Headers["Authorization"]; if (string.IsNullOrEmpty(authHeader) || !authHeader.StartsWith("Bearer ")) return false; // 401 Unauthorized var token = authHeader.Substring("Bearer ".Length).Trim(); try { var principal = ValidateAndDecodeJwt(token); operationContext.IncomingMessageProperties["Principal"] = principal; return true; } catch { return false; } } private IPrincipal ValidateAndDecodeJwt(string token) { var handler = new JwtSecurityTokenHandler(); var key = Encoding.UTF8.GetBytes(_configuration["Jwt:SecretKey"]); handler.ValidateToken(token, new TokenValidationParameters { ValidateIssuerSigningKey = true, IssuerSigningKey = new SymmetricSecurityKey(key), ValidateIssuer = true, ValidIssuer = _configuration["Jwt:Issuer"], ValidateAudience = true, ValidAudience = _configuration["Jwt:Audience"], ClockSkew = TimeSpan.Zero }, out _); // Return claims principal with role information } }

Esfuerzo: 20-30 horas-hombre | Risk reduction: 95% (elimina acceso anónimo)

1.3 Aislamiento de Credenciales por Hospital MEDIO

Problema: Contraseña cmrservice05 compartida entre 9 servidores y 10 hospitales.

Solución: Implementar sistema de gestión de secretos (HashiCorp Vault / AWS Secrets Manager) con rotación automática y credenciales únicas por hospital.

Implementación:

# Política de Vault para CMR path "secret/cmr/*" { capabilities = ["read", "list"] } path "secret/cmr/corominas" { capabilities = ["read"] control_group = { factor "approval" { identity { group = "security-team" } } } } # Rotación automática cada 30 días vault write secret/cmr/corominas/tablet-password \ value=$(openssl rand -base64 32) \ ttl="720h"

Esfuerzo: 30-40 horas-hombre | Risk reduction: 100% (elimina riesgo de password compartido)

Dominio 2: Hardening de Infraestructura

Objetivo: Eliminar exposición innecesaria de información de servidores, directorios y metadatos.

Hallazgos referenciados: CMR-09, CMR-10, CMR-11, CMR-12

2.1 Migración Completa a HTTPS ALTO

Hosts afectados: www.cmr-apps.com, disanjose.ddns.net:99

Implementación: Certificados Let's Encrypt vía Certbot + renovación automática. Configuración de redirect HTTP→HTTPS a nivel de aplicación y firewall.

# Nginx - redirect HTTP a HTTPS server { listen 80; server_name www.cmr-apps.com; return 301 https://$server_name$request_uri; } server { listen 443 ssl; server_name www.cmr-apps.com; ssl_certificate /etc/letsencrypt/live/www.cmr-apps.com/fullchain.pem; ssl_certificate_key /etc/letsencrypt/live/www.cmr-apps.com/privkey.pem; # TLS 1.3 only + HSTS ssl_protocols TLSv1.3; add_header Strict-Transport-Security "max-age=63072000" always; }

Esfuerzo: 8-16 horas-hombre | Risk reduction: 100% (elimina PHI en texto plano)

2.2 Deshabilitar Directory Listing BAJO

Servidores afectados: CEDISA (IIS 8.5), CMM (IIS 10.0)

# IIS web.config - deshabilitar directory listing <configuration> <system.webServer> <directoryBrowse enabled="false" /> <security> <requestFiltering> <hiddenSegments> <add segment="Certificados" /> <add segment="Xml" /> </hiddenSegments> </requestFiltering> </security> </system.webServer> </configuration>

Esfuerzo: 2 horas-hombre | Risk reduction: 100%

2.3 Remover Server Headers y Fingerprinting BAJO

Implementación: Eliminar headers X-AspNet-Version, X-Powered-By, Server de las respuestas HTTP.

# IIS - URL Rewrite para remover headers <system.webServer> <httpProtocol> <customHeaders> <remove name="X-Powered-By" /> <remove name="Server" /> </customHeaders> </httpProtocol> <security> <requestFiltering removeServerHeader="true" /> </security> </system.webServer>

Esfuerzo: 2 horas-hombre | Risk reduction: 30% (dificulta fingerprinting)

Dominio 3: Seguridad de Aplicaciones

Objetivo: Eliminar configuraciones inseguras en las apps Flutter.

Hallazgos referenciados: CMR-08, CMR-14

3.1 Desactivar debugMode en Producción MEDIO

Apps afectadas: 10 de 14 apps Flutter

Implementación: Modificar configuration.yaml en cada app. El proceso requiere rebuild y publicación de nuevas versiones en Google Play.

# configuration.yaml - antes debugMode: true # configuration.yaml - después debugMode: false

Esfuerzo: 16-24 horas-hombre (incluye CI/CD + publicación en stores) | Risk reduction: 60%

3.2 Remover usesCleartextTraffic BAJO

App afectada: Clínica Abreu

# AndroidManifest.xml - antes <application android:usesCleartextTraffic="true" ...> # AndroidManifest.xml - después <application android:usesCleartextTraffic="false" ...>

Esfuerzo: 2 horas-hombre | Risk reduction: 100%

3.3 Implementar Network Security Config BAJO

Configuración de seguridad de red en Android para permitir solo conexiones HTTPS con certificados de confianza.

# res/xml/network_security_config.xml <?xml version="1.0" encoding="utf-8"?> <network-security-config> <base-config cleartextTrafficPermitted="false"> <trust-anchors> <certificates src="system" /> </trust-anchors> </base-config> </network-security-config>

Dominio 4: Rate Limiting y Protección WSDL

Hallazgos referenciados: CMR-03, CMR-07, CMR-13

4.1 Rate Limiting por Endpoint y Cliente MEDIO

Implementación WCF: Usar WCF Extensibility con IEndpointBehavior para implementar throttling por IP y por token.

// WCF Rate Limiting Behavior public class RateLimitingBehavior : IEndpointBehavior { private readonly MemoryCache _cache = MemoryCache.Default; private readonly int _maxRequests = 30; private readonly int _windowSeconds = 60; public void ApplyDispatchBehavior(ServiceEndpoint endpoint, EndpointDispatcher endpointDispatcher) { endpointDispatcher.DispatchRuntime.MessageInspectors.Add( new RateLimitingInspector(_cache, _maxRequests, _windowSeconds)); } } public class RateLimitingInspector : IDispatchMessageInspector { public object AfterReceiveRequest(ref Message request, IClientChannel channel, InstanceContext instanceContext) { var ip = GetClientIp(); var key = $"ratelimit:{ip}"; var count = (int?)_cache.Get(key) ?? 0; if (count >= _maxRequests) throw new FaultException("Rate limit exceeded. Try again later."); _cache.Set(key, count + 1, DateTimeOffset.UtcNow.AddSeconds(_windowSeconds)); return null; } }

Esfuerzo: 16-24 horas-hombre | Risk reduction: 80% contra fuerza bruta

4.2 Protección de WSDL BAJO

Opción 1: Deshabilitar metadata exchange en producción.

# Web.config - deshabilitar serviceMetadata <behaviors> <serviceBehaviors> <behavior name="SecureBehavior"> <!-- REMOVER o comentar esta línea --> <serviceMetadata httpGetEnabled="true" /> </behavior> </serviceBehaviors> </behaviors>

Opción 2: Restringir acceso por IP al metadata endpoint.

# IIS - Restringir WSDL por IP <location path="ServicioPortal.svc"> <system.webServer> <security> <ipSecurity allowUnlisted="false"> <add ipAddress="192.168.0.0" subnetMask="255.255.0.0" allowed="true" /> <add ipAddress="10.200.200.0" subnetMask="255.255.255.0" allowed="true" /> </ipSecurity> </security> </system.webServer> </location>

Esfuerzo: 2-4 horas-hombre | Risk reduction: 100% (elimina mapa de ataque público)

Dominio 5: Monitoreo y Detección

Objetivo: Implementar capacidad de detección de intrusiones y respuesta a incidentes.

Hallazgos referenciados: CMR-08, CMR-14 (sistémico)

5.1 SIEM Centralizado con WCF Logging ALTO

Implementación: WCF custom MessageInspector que loggea TODAS las llamadas a endpoints (IP, método, timestamp, éxito/fallo) a un SIEM central (Wazuh / ELK / Sentinel).

# Log format (JSON a SIEM): { "timestamp": "2026-07-14T22:00:00Z", "endpoint": "PersonalRecuperar", "client_ip": "190.167.33.178", "auth_type": "none", "success": true, "records_returned": 506, "server": "portal.clinicacorominas.com.do", "hospital": "corominas" } # Reglas de alerta SIEM: # ALERT: >100 llamadas/min a PersonalRecuperar → posible exfiltración # ALERT: Llamada a GetContrasenaTabletas desde IP externa → breach # ALERT: Misma IP llamando a >3 hospitales diferentes → attacker scanning

Esfuerzo: 40-60 horas-hombre | Risk reduction: 85% (detección temprana)

5.2 Endpoint Detection and Response (EDR) ALTO

Instalar Wazuh agent en todos los servidores Windows (IIS) para monitoreo de integridad de archivos, detección de malware y correlación de eventos de seguridad.

Esfuerzo: 20-30 horas-hombre | Risk reduction: 70%
