⚠ Data Breach Crítico — 7,452 Registros Expuestos

Null Session Intelligence LLC identificó una vulnerabilidad crítica en la configuración de Firebase Firestore que permite a cualquier usuario autenticado leer la base de datos completa de usuarios de DDTeAyuda. La vulnerabilidad sigue activa al momento de este informe. Se incluye evidencia real y guía de remediación paso a paso.

Resumen Ejecutivo

Durante una evaluación de seguridad realizada el 9 de julio de 2026, NSI identificó que las reglas de seguridad de Firebase Firestore del proyecto ddt-te-ayuda permiten que cualquier usuario con una cuenta gratuita acceda a la totalidad de los 7,452 perfiles registrados en la plataforma. La vulneración incluye datos personales de ciudadanos dominicanos, siendo los más críticos los números de cédula de identidad dominicana (3,807 expuestos), utilizados para identificación nacional, trámites bancarios y gubernamentales.

NSI-001: Firestore Sin Restricciones

Exposición Masiva de Datos Personales — Data Breach Activo

AtributoValor
Tipo de VulnerabilidadControl de Acceso Impropio (CWE-284) — Firestore Rules

Descripción

Las reglas de seguridad de Firebase Firestore están configuradas para permitir que cualquier usuario autenticado lea todos los documentos de la colección profiles, sin importar si el perfil le pertenece o no. Cualquier persona con una cuenta gratuita en la aplicación puede extraer la totalidad de los datos de la plataforma.

Impacto en República Dominicana: Los números de cédula (3,807 expuestos) son el documento de identificación nacional oficial del país. Su exposición conlleva riesgo inmediato de robo de identidad, fraude financiero y suplantación en trámites gubernamentales.

Pasos para Reproducir

  1. Crear una cuenta gratuita en la aplicación DDTeAyuda (o usar Firebase Auth REST API)
  2. Obtener el token de autenticación (idToken) de la respuesta de Firebase
  3. Enviar una solicitud GET a la API REST de Firestore con el token
  4. Paginizar usando nextPageToken — se obtienen los 7,452 registros en ~131 páginas

# Paso 1: Autenticarse (cualquier email funciona)

Guía de Corrección — NSI-001

Firestore Rules: Antes y Después

Reglas Actuales (VULNERABLES — NO USAR)

// ❌ CUALQUIER usuario autenticado puede leer TODOS los perfiles
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /profiles/{profileId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null;
    }
  }
}

Reglas Corregidas (SEGURAS)

// ✅ Cada usuario solo puede leer SU PROPIO perfil
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Perfiles de usuario
    match /profiles/{profileId} {
      allow read, create, update: if request.auth != null
        && request.auth.uid == profileId;
      allow delete: if false;
    }

    // Catálogo de servicios (público)
    match /services/{serviceId} {
      allow read: if true;
      allow write: if request.auth != null
        && request.auth.token.role == 'admin';
    }

    // Solicitudes de servicio (solo involucrados)
    match /solicitudes/{solicitudId} {
      allow read: if request.auth != null
        && (resource.data.client_id == request.auth.uid
            || resource.data.supplier_id == request.auth.uid);
      allow create: if request.auth != null;
    }
  }
}

Paso a Paso — Aplicar la Corrección

  1. Acceder a Firebase Console: console.firebase.google.com
  2. Ir a Firestore Database → Reglas
  3. Reemplazar las reglas actuales con las reglas seguras (arriba)
  4. Hacer clic en PUBLICAR
  5. Ir a la pestaña Simulador de Reglas y verificar:
    • Usuario autenticado leyendo su propio perfil → ✅ Permitido
    • Usuario autenticado leyendo otro perfil → ❌ Denegado
    • Solicitud sin autenticación → ❌ Denegado

Proteger Cuentas Admin

Implicaciones de Stripe y PCI DSS

Riesgo de Cumplimiento PCI DSS

La aplicación DDTeAyuda integra Stripe para procesamiento de pagos con tarjetas de crédito. La colección payment_cards en Firestore — aunque actualmente bloqueada — representa un riesgo regulatorio significativo.

Lo que Stripe Exige (Términos de Servicio)

RequisitoTexto de StripeRiesgo
Seguridad de datos de pago "You must maintain appropriate administrative, technical, and physical security to prevent unauthorized use or access to your Stripe Account and Payment Data." ALTO
Notificación de breach "You must notify Stripe immediately of any unauthorized use of your Stripe Account or any breach of security." ALTO
No almacenar PAN/CVV "You must not store full card numbers (PAN), CVV codes, or magnetic stripe data." (PCI DSS Rule 3.2) CRÍTICO

Escenarios según qué almacena payment_cards

Dato almacenadoCumplimiento PCIConsecuencia de breach
Solo token Stripe (pm_xxx, cus_xxx) 🟢 Cumple — Stripe tokeniza Riesgo bajo. Stripe revoca tokens y emite nuevos
Últimos 4 dígitos + fecha exp. 🟡 Permitido (PCI DSS 3.3) Riesgo medio. No permite transacciones sin token
Número completo (PAN) 🔴 Violación PCI DSS Multas $5K-$100K/mes + posible cierre de cuenta Stripe + forense obligatorio
CVV almacenado 🔴 Prohibido (PCI DSS 3.2) Cierre inmediato de cuenta Stripe. Posibles acciones legales

Análisis forense de la app

Del análisis del APK, la app utiliza:

  • payment_method_service.dart — servicio de métodos de pago
  • agregar_tarjeta_screen.dart — pantalla para añadir tarjetas
  • detalle_tarjeta_screen.dart — detalle de tarjetas guardadas
  • Flutter credit card package (flutter_credit_card) — UI de tarjetas
  • Stripe SDK de Firebase (presente en dependencias del APK)

La colección payment_cards no fue accesible para verificar su contenido exacto, pero:

  • Si usa Stripe PaymentIntents + SetupIntents correctamente → solo guarda tokens ✅
  • Si almacena datos de tarjeta en Firestore para mostrar al usuario → podría estar violando PCI DSS si guarda más de los últimos 4 dígitos

Recomendaciones PCI DSS para DDTeAyuda

  1. Auditar payment_cards inmediatamente — verificar qué campos se almacenan en Firestore
  2. Usar Stripe SetupIntents si se necesita guardar tarjetas para futuros pagos (el token Stripe es suficiente)
  3. Nunca almacenar PAN completo ni CVV — ni siquiera cifrados
  4. Notificar a Stripe si existió exposición de datos de pago como parte del breach general
  5. Completar el SAQ (Self-Assessment Questionnaire) de PCI DSS para validar cumplimiento

Protocolo de Emergencia

Si no puede aplicar la corrección de Firestore en 24 horas, siga este protocolo:

  1. Deshabilitar temporalmente el proyecto Firebase desde Google Cloud Console
  2. Eliminar las API keys expuestas desde Google Cloud Console → Credenciales
  3. Deshabilitar registro de nuevos usuarios en Firebase Authentication → Sign-in methods
  4. Notificar a INDOTEL (Instituto Dominicano de las Telecomunicaciones) como autoridad de protección de datos en República Dominicana
  5. Contratar verificación post-corrección con NSI LLC para certificar que la vulnerabilidad fue cerrada completamente

Notificación a Usuarios Afectados

La ley de protección de datos de República Dominicana (Ley 172-13) requiere notificar a los titulares de datos personales cuando ocurre una brecha de seguridad. Se recomienda enviar un correo a los 7,432 usuarios informando:

  • El tipo de datos expuestos (nombre, email, teléfono, cédula, dirección)
  • La fecha y circunstancias de la brecha
  • Las medidas correctivas implementadas
  • Recomendaciones para protegerse (cambio de contraseña, monitoreo de crédito, alerta de cédula)
  • Un canal de contacto para preguntas
